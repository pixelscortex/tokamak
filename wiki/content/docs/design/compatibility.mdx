This page describes the parked Blitz route (TKM-121) and no longer limits design work.

The goal is to run ui-sdk's behaviours on our renderer without moving to a
webview. This page is the working list: each row is a browser API a library
expects, where we stand, and what kind of work closes it. Update a row when its
status changes.

## Where we are

A spike on branch `spike/ui-sdk-dom` (not merged) ran a ui-sdk menu on the
renderer: a button opens a five-item menu beside it, the arrow keys move focus,
Enter activates, and Escape or a press outside closes it and returns focus. The
behaviour comes from `@ui-sdk/core` 0.1.0-beta.6 (`definePrimitive`,
`createRovingFocus`, `bindLayer`), through an opt-in DOM layer in
`packages/render/js/dom/` and a 25-line Solid 1.9 adapter. Two headless native
tests cover it. Solid and Blitz were not changed.

The spike's full report is `spikes/ui-sdk-dom/REPORT.md` on that branch.

Not verified by the spike: a real window with physical input, GPU output,
screen readers, ui-sdk's full popup (`createPopup`), and any component other
than this menu.

## Status words

- **Have:** works in the spike's DOM layer and is covered by a native test.
  "Limited" means only the part the menu needed.
- **Wiring:** JavaScript only. Our renderer owns the tree, so the answer can be
  computed in QuickJS.
- **Bridge:** needs a call into Rust and back. Blitz already holds the answer.
- **Engine:** needs Blitz itself to change.
- **Unchecked:** nobody has looked yet.

The "uses" column counts how often `@ui-sdk/core` refers to the API in its 388
built files, from a text search. It shows roughly how much depends on a row.

## Solid

- A small adapter of our own from `@ui-sdk/core` to Solid 1.9 works for this
  menu. Moving to Solid 2 would not help: ui-sdk's own Solid adapter targets
  browser elements, not our renderer.
- The adapter uses `@ui-sdk/core/renderer`, which ui-sdk says is not public
  API and may change in any release. Pin the version and keep native tests.
- ui-sdk's types name browser globals. Adding the DOM type library to the
  client broke Solid's JSX types, so the adapter asserts the type in one place.

## What is left

Rough estimates from the spike, for a tested common subset and not all of
ui-sdk:

1. **Wiring, about 1–2 weeks:** full selectors, `TreeWalker`, mutation
   records, richer events, `AbortController`, element styles, timers. `Intl` is
   extra.
2. **Bridge, about 2–4 weeks:** measurement after layout, computed styles,
   frame callbacks, scrolling, consistent focus events, and a reusable adapter.
   This is what the full popup needs.
3. **Engine:** only a true top layer and `:focus-visible`. Nothing else was
   shown to need a Blitz change.
