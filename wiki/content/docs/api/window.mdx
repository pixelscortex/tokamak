Import the window API from `@tokamak/sdk/client`. Export pages, components
and actions from your plugin's `src/client/api.tsx` so the build can discover them.

## Pages and components

`view` gives a page a literal route and can supply its title and icon.
The build publishes typed paths under `parts` for plain JSX elements. Path
segments follow the render function and its JSX ancestry, using a static
`data-part` or `id` when present, and the tag name otherwise.

```tsx
import { view } from "@tokamak/sdk/client";

export const Composer = () => (
  <section>
    <button>Send</button>
  </section>
);

export const Work = view({ route: "/work", title: "Work" }, () => <Composer />);
```

## Actions on elements

Import another plugin's window entry through `plugin:example/client`.
An action targets a component's published path, such as `parts.Composer.section.button`.

| Action    | Effect                                                                   |
| --------- | ------------------------------------------------------------------------ |
| `before`  | Add a sibling immediately before the element.                            |
| `after`   | Add a sibling immediately after it.                                      |
| `prepend` | Add a child at the start.                                                |
| `append`  | Add a child at the end.                                                  |
| `wrap`    | Surround the current element, which arrives as `props.children`.         |
| `replace` | Swap in another element and dispose of the original and its descendants. |
| `hide`    | Remove the element, its children, and additions before and after it.     |

Use `{ when: (props) => condition }` to make an action conditional. The
check is reactive and receives the declaring component's props, including
`$row.item` and `$row.index` inside a `For` row. The
`order` option sorts actions at the same position (default 0, then plugin ID).
Only the first installed replacement owns a target.

## State

Read a value with `value()` and update it with `value.set(next)` or a
pure updater. `derived(() => value() * 2)` returns a read-only, reactive
computation. Both follow Solid's tracking rules.

| `keep`     | Where the value lasts                                   |
| ---------- | ------------------------------------------------------- |
| Omitted    | In the current window.                                  |
| `"device"` | On this device across window restarts.                  |
| `"me"`     | On the server for the signed-in member, across devices. |

Kept state needs the plugin build. Declare it at module scope with a stable
variable name so the build can give it a stable storage key.
