title: Architecture
description: A Rust server, TypeScript plugins, and a web client in Tauri.

The server owns plugins, storage, scheduling, and live queries. Clients connect
over the SDK WebSocket protocol and never open storage.

```text
app/                              packages/server/
Solid 2 + TanStack Router         plugin catalog and asset snapshots
browser DOM in Tauri 2  <------>  QuickJS workers in packages/engine
SDK WebSocket transport          embedded SurrealDB / SurrealKV
```

## Server

Server plugins use the portable `@tokamak/sdk` API. Queries read snapshots;
mutations share a transaction across nested calls. Committed footprints drive
live query invalidation. Actions perform external effects through host
capabilities. Opted-in worker plugins run actions in Bun; queries and mutations
stay in QuickJS. The client uses the system webview’s JavaScript engine.

The server validates plugin identities, dependencies, hashes, and public
contracts before installation. Assets are served from verified immutable
snapshots. A failed reload preserves the previous generation.

## Client

`@tokamak/app` is a client-rendered Solid 2 web app. It uses TanStack Router,
Tailwind 4, and ui-sdk controls. There is no SSR or meta-framework. Tauri supplies
the native window and a drag capability. The current development helper starts
the existing server separately with a disposable loopback store.

The skeleton has a live thread list at `/` and a controls page at `/kit`.
The shared UI package is empty. Chat's old client source is retained for its
rewrite and excluded from the build.

## Plugin UI

The author API remains unchanged. The SDK supplies DOM contexts, live queries,
slots, fills, wrappers, and replacements. Static analysis preserves the
compiler-qualified contribution identities.

Plugin UI compilation is disabled while the web ESM target is built. Server
artifacts omit `entries.ui`. The reusable catalog and generation lifecycle code
lives in `@tokamak/runtime/plugins`; it has no evaluator. The next loader must
use server-provided modules and share host runtime identities. Plugin isolation,
server discovery/authentication, and desktop server packaging remain open work.

The former renderer route is parked under TKM-121. It no longer constrains web
design. See [Design rules](/docs/design) and [Plugin installation](/docs/server/plugins).
