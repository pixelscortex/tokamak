title: Hosting
description: Run the server and web UI in one container.
---

Build and run locally:

```sh
docker build -t tokamak .
# Generate a private token of at least 32 characters; don't commit it.
export TOKAMAK_ACCESS_TOKEN="$(openssl rand -hex 32)"
docker run --name tokamak -p 3000:3000 \
  -v tokamak-data:/data \
  -e TOKAMAK_ACCESS_TOKEN \
  -e TOKAMAK_PUBLIC_URL=http://localhost:3000 tokamak
```

## Joining a server

Create a separate invite for each person: `https://<address>/join#<token>`. The token sits in the URL
fragment, so a browser that opens the link never sends it to the server in the
request. `<address>#<token>` and a bare address work too; with a bare address,
"Add a server" asks for the token.

- **Desktop app:** open the server switcher at the top of the sidebar (with the
  sidebar hidden, the server button in the top strip) and choose **Add server…**.
  Paste the invite or the address. The app checks that something answers at
  `/health`, then checks the token with the plugin catalog request, then asks for
  the name to show. Plain `http://` is accepted only for a loopback address.
- **Browser:** open the invite link, or open `http://localhost:3000` and choose
  **Add invite**. A page served by the server talks only to that server.

The app keeps joined servers, their tokens and your name in localStorage on that
device (the browser keeps it per origin). Remove a server from the switcher to
forget its token.
Each invite identifies a member. Every signed-in member can read and write every
thread; there are no per-thread permissions yet. Use HTTPS
when exposing the server remotely. Disable proxy query-string logging: WebSocket
and plugin requests carry the token as `?token=` (HTTP also accepts Bearer auth).
Tokens are never included in server logs.

## Temporary members and invites

The bootstrap `TOKAMAK_ACCESS_TOKEN` continues to identify the owner (`id: owner`).
Set `TOKAMAK_OWNER_NAME` to the owner's initial name (default `Owner`). Existing
saved connections keep working. Hosted mode still requires this bootstrap token.
These temporary identities will be replaced by real accounts later.

Run these commands on your own machine; they call the server over HTTPS:

```sh
export TOKAMAK_TOKEN='<owner token>'
tokamak invite 'Alice' --server https://tokamak.example.app
tokamak members --server https://tokamak.example.app
tokamak revoke '<member id>' --server https://tokamak.example.app
```

Alternatively pass `--token '<owner token>'` to each command. `invite` prints only
the invite URL, exactly once; save it before closing your terminal. Tokens contain
256 random bits encoded as URL-safe hex. `members` lists ID, name, role, created
and revoked timestamps (milliseconds since the epoch), never token hashes or tokens.
Revocation closes that member's open WebSockets and rejects future connections.
The bootstrap owner cannot be revoked; rotate its environment token instead.
HTTP is accepted by the CLI only on loopback for local testing.

Members are stored in `members.json` beside the `--data` store directory: the
image's `/data/store` uses `/data/members.json`. Each row contains
`{ id, name, role, token_hash, created_at, revoked_at? }`. Only SHA-256 hashes are
stored; the file is replaced atomically with private permissions. Keep it with
your data volume. Owner renames persist; `TOKAMAK_OWNER_NAME` supplies the initial
name when the owner row is first created.

Built-in HTTP operations accept `Authorization: Bearer <token>`:

- `POST /members` with `{"name":"Alice"}` returns the new token once.
- `GET /members` lists members; `POST /members/<id>/revoke` revokes one.
- `GET /account` returns your `{ id, name, role }`.
- `POST /account` with `{"name":"Alice"}` changes your own name. Names must have
  1–100 characters and no control characters.

Member management, plugin reload and shutdown are owner-only (403 for members).
`/account` also accepts `?token=` for browser requests, like `/ws` and `/plugins`.
The existing connect form sends its saved display name after connecting when it
differs from the server's name. No new sign-in UI is required.

Plugins receive the authenticated caller as `ctx.user` in every query, mutation
and action, including subscriptions and calls through other plugins. The built-in
WebSocket query `tokamak:whoami` with `{}` returns the same identity. Desktop/local
mode uses `{ id: "local", name: "You", role: "owner" }`; `TOKAMAK_OWNER_NAME` can
override that local name. Chat user messages snapshot `author: { id, name }`;
assistant messages snapshot `askedBy: { id, name }` when the run starts. Old rows
without these optional fields stay valid, and later renames do not rewrite history.

The image includes only the chat plugin. Threads can be created and saved; the
agent picker is empty until agents on users' machines are connected. No agent
processes run in this image. JavaScript runs in the server's embedded QuickJS;
chat needs no external Bun, Node, or agent runtime in the final image.

| Setting                                 | Purpose                                                                                                                                                                                                                                                    |
| --------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `TOKAMAK_ACCESS_TOKEN`                  | Required in hosted mode; at least 32 characters.                                                                                                                                                                                                           |
| `TOKAMAK_WEB_DIR` / `--web <directory>` | Built web directory; flag overrides env. Enables hosted mode.                                                                                                                                                                                              |
| `TOKAMAK_PUBLIC_URL`                    | Public HTTP(S) origin, e.g. `https://tokamak.example.app`. Automatically accepted by the WebSocket/plugin origin allowlist, including behind a TLS proxy. Direct HTTP also accepts the request host automatically; set this explicitly for an HTTPS proxy. |
| `TOKAMAK_ALLOWED_ORIGINS`               | Optional comma-separated additional browser origins (replaces desktop/dev defaults). The public origin is always included.                                                                                                                                 |
| `PORT`                                  | Without `--listen`, binds `0.0.0.0:$PORT`. Image default: `3000`.                                                                                                                                                                                          |
| `--listen <address:port>`               | Overrides `PORT`. Outside hosted mode, only loopback is allowed.                                                                                                                                                                                           |
| `--data <directory>`                    | Persistent store directory; image uses `/data/store`. Created on first start and reused on restart.                                                                                                                                                        |
| `--plugins <directory>`                 | Plugin artifact root; image contains only `/opt/tokamak/plugins/chat`.                                                                                                                                                                                     |

Mount a volume at `/data` and keep it across container replacements. The container
runs as UID 10001; bind mounts must be writable by that user. The healthcheck uses
public `/health`. The shell HTML, JavaScript and CSS are public so the connect
form can load; `/ws`, the plugin catalog and all plugin assets require the token.
A rejected token on those routes answers 401 with the CORS header for an allowed
origin, so the app can say "invite not accepted" instead of "unreachable".
Hashed shell assets cache for a year; HTML uses `no-cache`. API routes take priority
over client-side navigation fallback. Desktop `--local-dir` is separate and cannot
be combined with `--web`.

For Railway: deploy using the root Dockerfile, attach a volume at `/data`, and set
`TOKAMAK_ACCESS_TOKEN` and `TOKAMAK_PUBLIC_URL` to the service's public HTTPS origin.
Railway supplies `PORT`. Termination signals close the store cleanly. Run one
replica per volume; the embedded store owns an exclusive lock.

Railway mounts volumes as root, and the image runs as a non-root user. Set
`RAILWAY_RUN_UID=0` on the service so the server can write to `/data`. The
Dockerfile has no `VOLUME` line because Railway attaches the volume itself.
